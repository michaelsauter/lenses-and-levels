The Lenses & Levels LLM Skill

The Lenses & Levels LLM Skill equips AI coding assistants and language models (such as Claude Code, Cursor, Copilot, ChatGPT, and other agentic tools) with instructions to author, decompose, and audit architecture documentation according to the framework.

View on GitHub

Two Operating Modes

The skill operates in two distinct modes depending on your workflow:

Mode A: Text Ingestion & Splitting

When given unstructured text (e.g. PRDs, RFCs, meeting notes, or legacy drafts), the assistant decomposes the content across the 15 architectural lenses and 3 detail levels:

  • Canonical Lens Mapping: Categorizes architectural concerns into the appropriate lenses (System, Capability, Domain, Data, Integration, Runtime, Deployment, Security, etc.).
  • Overview Discipline (Centrality Filter): Keeps Level 1 (Overview) strictly focused on high-level mental models and narratives. Non-central edge cases, parameters, and low-level code are systematically demoted to Level 2 or 3.
  • Single Source of Truth: Never copies the same specification twice. Assigns canonical ownership to one lens and generates cross-references in others.
  • Downward Self-Containment: Ensures that engineers reading Level 3 (Detail) have all necessary local context and never need to jump back up to Level 1.

Mode B: Documentation Assessment & Continuous Audit

When given a documentation directory or repository path, the assistant audits the files for consistency and architectural drift:

  • Lens Placement Check: Flags content in the wrong lens (e.g. database schemas in the System Lens instead of Data Lens, CI/CD pipelines in Runtime Lens instead of Deployment Lens).
  • Level Placement Check: Identifies overview bloat where Level 1 is overloaded with minutiae, or Level 2 fails to provide a navigation map.
  • Duplication Detection: Identifies redundant copy across files and replaces it with structured reference links.
  • Upward Dependency Traps: Catches phrases like "as explained in Level 1 above" that break reader flow in lower levels.
  • Actionable Report & Diffs: Generates a full audit scorecard, findings list, and ready-to-merge refactoring diffs.

The 4 Invariants Enforced by the Skill

1. Zero Duplication (SSOT)

Information belongs to exactly one canonical lens. Cross-cutting concerns are referenced via direct markdown links, preventing drift and synchronization bugs.

2. Downward Self-Containment

Lower levels (Level 2 & Level 3) are completely self-contained. Implementers and auditors can execute tasks directly from Level 3 without having to jump back up to Level 1.

3. Overview Discipline

Level 1 covers strictly central aspects to build a mental model in under 5 minutes. Peripheral details, specific parameters, and edge cases are demoted to lower levels.

4. Living Artifact Anchoring

Level 3 avoids brittle static prose by linking directly to living artifacts: OpenAPI specs, Terraform code, database migrations, and ADRs.

Installation & Usage

Add the skill into your project's .skills/ directory (the .skills/ directory is kept local and uncommitted via .gitignore): 

# Install into your project's .skills directory (uncommitted)
mkdir -p .skills
git clone --depth 1 https://github.com/michaelsauter/lenses-and-levels.git /tmp/l-and-l && \
  cp -r /tmp/l-and-l/skills/lenses-and-levels .skills/ && \
  rm -rf /tmp/l-and-l

Once installed, ask Claude Code, Cursor, or your preferred assistant to use it:

  • Decomposing unstructured text: "Read .skills/lenses-and-levels/SKILL.md and split the following text into the appropriate lenses and levels."
  • Auditing existing documentation: "Using .skills/lenses-and-levels/SKILL.md, audit the documentation in ./docs for lens placement, overview bloat, and cross-lens duplication."

You can also run the bundled auditor script directly from your terminal: 

python3 .skills/lenses-and-levels/scripts/audit_docs.py --path ./docs

Using with Web & Chat LLMs

For chat-based assistants (Claude.ai, ChatGPT), you can copy the prompt instructions directly:

You are an expert software architect specialized in the "Lenses & Levels Architecture Documentation Model".
When authoring or reviewing documentation:
1. Decompose content across the 15 Lenses and 3 Levels (Level 1: Overview, Level 2: Map, Level 3: Detail).
2. Enforce Overview Discipline: Level 1 must be concise, visual, and strictly central; demote edge cases and code to Level 2/3.
3. Eliminate duplication across lenses: use canonical owners and markdown cross-references.
4. Ensure downward self-containment: Level 2 and Level 3 must be self-contained with zero upward dependency traps.
5. In Level 3, link to living artifacts (OpenAPI, Terraform, migrations, ADRs) rather than retyping static prose.
